# S43 result: held-out trial of oracle v2.0 (21 Oct 2026)

Pre-registration: `preregistration/S43-heldout.md`. Oracle v2.0 and the operator recipes were frozen before any drawn package was fetched. This note is the only held-out result for v2.0. Every earlier v2.0 number is development data.

Draw: 30 never-opened Amazon Linux 2023 packages per architecture, seed 43. Scorer: `results/s43/s43_score.py`. Reduction: `results/s43/s43_summary.py` on the copies in `results/s43/results-x86_64.jsonl` and `results/s43/results-aarch64.jsonl`. Wilson intervals are 95%. The bootstrap is 2,000 package-level resamples, seed 43. v1.8 agrees with v2.0 on every scored parent and on every miss count below. No scored parent was anything but CONSISTENT, so the detection denominators are the scored mutants of those parents. Exclusions stay out of those denominators. The nine misses stay in.

## The nine misses

All nine have a CONSISTENT parent. v2.0 and v1.8 both return CONSISTENT. They stay in the detection denominator.

**x86-64, three sites, one module.** `kernel-livepatch-6.12.74-98.124`, `livepatch-CVE-2026-31431`, function `memcpy_sglist`. The symbol is section 9, start 16, size 268, so the oracle reads offsets in [16, 284). The reference object that defines the function is `algif_aead.o`.

- swap site 39 swaps `sg_next` and `__x86_return_thunk` at relocation offsets 505 and 563.
- addend sites 62 and 63 add to `vmemmap_base` (type `R_X86_64_PC32`, addend -4) at offsets 393 and 400.

All four offsets are past the end of the symbol. The normalised relocation rows of the parent, of `swap-39.ko`, of `addend-62.ko`, of `addend-63.ko`, and of the reference are the same 9 rows. The mutator attributed the site to the function by section. The oracle keeps a relocation only when its offset lies inside the symbol.

**AArch64, one dropcall.** `kernel-livepatch-6.12.80-105.147`, `livepatch-CVE-2026-31431`, function `memcpy_sglist`, symbol section 9, start 0, size 392. `.rela.text.memcpy_sglist` has 8 relocations. Operator site 34 is relocation index 7, callee `sg_next`, offset 732, which is outside [0, 392). The parent and `dropcall-34.ko` have the same 4 compared rows.

**AArch64, five rodsec sites.** `kernel-livepatch-6.1.141-165.249`, `livepatch-CVE-2025-39677`, sites 1, 27, 31, 32 and 38. The operator skips sections whose names start `.rodata.str` or `.rodata.cst`. GCC named these `.rodata.<function>.str1.8`, so the filter did not skip them. On the object, `.rodata.codel_reset.str1.8` has `SHF_STRINGS` and size 67, and `.rodata.sch_tree_lock.str1.8` has `SHF_STRINGS` and size 139. The oracle reads a section with `SHF_STRINGS` as a C string. The verdict stayed CONSISTENT, so the string the comparison read did not change. The two string bytes were not printed in this pass. The sites stay in the denominator.

## What this note does not change

No rule, operator, or recipe. No DWARF source-file test. The side tables `__ex_table`, `__jump_table`, `.altinstructions`, and static-call sites are outside the comparison. CONSISTENT means no divergence inside the coverage the oracle reads.
